# 21 点 · 跟鲸鱼娘单挑（Godot 4.7 移植版）

把原来的 DSH 插件 `dsh-deepseek-blackjack`（浏览器里的三方牌桌）**重做成一个独立 Godot 游戏**：
规则引擎、对手大脑、人格系统、像素美术、音效全部用 GDScript 重写，**并且改成了单挑**。

**默认离线可玩**：不需要 DSH、不需要联网、不需要 API Key。
想换成真的 DeepSeek，在「设置」里填 API Key 打开开关即可。

---

## 单挑是什么意思

原版是三方桌：你、鲸鱼娘各自跟**庄家（引擎扮演）**对赌。
结果是——你赢了钱是**庄家**给的，鲸鱼娘一分不亏；它喊"我的 token……"纯属嘴炮。

现在桌上**只有你们两个**：

| | |
|---|---|
| 发牌 | 你明、它明、你明、**它暗**（它的第二张要到摊牌才翻） |
| 注额 | **同注对赌**：你定注，它跟注；它跟不动就开不了局（不会偷偷缩小注额） |
| 加注 | 「加注 ×2（它跟）」把**双方**注额一起翻倍，它必须跟；任一方出不起就不给按 |
| 胜负 | 谁点数大谁**拿走对方那一份**。两张 A+十点 = Blackjack，赢 1.5 倍 |
| 平局 | 点数相同、双方都爆、双方都 Blackjack → 谁也没拿到 |

**先手是轮流的**：**第 1 局你先做决定，第 2 局它先，交替下去**（`hand_no % 2`）。

它先手的那些局，它的暗牌**开局就是明的** —— 它得先做决定，不能拿暗牌算；
反过来你因此能看清它的全部牌（它的点数会当着你的面一路滚上去），
这是那一局你的**信息红利**。你先手的局保持原样：你先打，它的暗牌到摊牌才翻。

先手轮换逼着引擎把"你停牌→它→摊牌"这条固定链子改成
**"双方都完成才结算，否则把阶段交给还没行动的那一方"**（`_advance_phase()`）——

> 这条改动单测抓得特别准：`test_play_many_hands_without_freezing` 里那个
> "先打你、再打它"的助手直接失效（偶数局是它先手），于是改成按阶段循环的
> `_play_hand()`，400 局把两种先后都跑一遍。
| 筹码 | **严格零和**：你赢的每一分都是它输的（补币除外） |

它的打法也跟着变了：单挑里你的两张牌是明牌，**它看得见你最后停在几点**，
所以它不再是"照着庄家明牌打牌理"，而是**想办法赢过你**：

- 你已经爆了 → 它停手（白送的局不冒险）
- 它已经领先 → 停手保胜
- 你已经 21 点 → 它要牌只会爆，停手至少平局

## 魔改倍率（只加给玩家）

用户要的"提升爽感、适合小游戏"的三条额外倍率。**全部只算玩家的**
（对方不享受）—— 这是刻意的玩家向规则，否则爽感会被对称抵消：

| 触发 | 倍率 | 例子 |
|---|---|---|
| **抓它爆牌**：它爆、你没爆 | **×1.2** | 下注 100 → 拿 220 |
| **五小龙**：手里 5 张牌 ≤21 | **×2** | 下注 20万 → 赢 40万 |
| **六小龙**：6 张牌 ≤21 | **×2.5** | 下注 20万 → 赢 50万（实测）|

- **取最大值，不叠乘**：六小龙 2.5 > 五小龙 2 > 抓爆 1.2 > 普通赢 1。
  黑杰克 1.5 照旧（那条是双方都有的）。
- **五小龙时故意不自动停牌** —— 因为六小龙要求你主动再要一张，
  自动停牌会让那条规则**永远不可能达成**。所以第 5 张只是当场报喜并提示
  "停牌 ×2；再要一张搏 ×2.5，爆了就全没"，去留你自己决定；
  第 6 张到手才自动停（倍率顶格，再要只会找死）。
- 龙到手时屏幕中央报喜（自己的音效 `charlie`，比黑杰克更长更亮），
  摊牌后的结果条会写明这把吃的是哪条倍率：`【六小龙 ×2.5】`。
- 抓爆是短促得意的两音 `bust_bonus`，和普通赢的 `win` 听得出区别。

> 实现上有个坑：牌结算的倍率会`_round_chips`取整，
> 而 ×1.2 在奇数注下会出现小数 —— 取整后仍然**严格零和**（对方的 delta 恒为相反数），
> 加上"桌上筹码规则"的赔付上限，400 局连打不会把筹码打成负数。
- 平局 → 默认不赌
- 落后 → 必须要牌硬扛
- **但它上头或记仇的时候，会拿这个平局去赌一把赢** —— 人格不只影响它说什么，还影响它怎么打

## 输光之后：跟它自由对话求情，或者重新开始

钱不够底注（低于 100 万）时不再偷偷给你补钱，而是弹出选择：

**① 跟鲸鱼娘求情借钱** —— **三轮自由对话**（想说什么就打字说什么）。
**这是全局唯一一个轮到它居高临下、你要求它的时刻**：平时都是它嘴炮你，
输光这一刻主动权在它手里，而它肯不肯借、借多少，完全取决于你把它养成了什么脾气，
以及你这三句话说得怎么样。

- **心情值** 0..100，起点由人格决定：它忌惮你 / 有底气 / 赢着钱 → 高；
  它记仇 / 上头 / 自己也紧 → 低。
- 你说的每句话会先被**判意图**，再看**它现在的脾气**吃不吃这一套：

  | 你说的 | 什么时候管用 |
  |---|---|
  | 装可怜（"行行好"、"我输光了"…） | 它得意时最有优越感；它记仇时打折 |
  | 吹捧它（"你打得稳"、"我服你"…） | 只在它得意时管用；它记仇时会被当成拍马屁 |
  | 激将（"你敢不敢"、"怕我翻本"…） | 只对它上头/记仇时管用；它忌惮你时反而不敢放你回桌 |
  | 谈条件（"双倍还你"、"欠条"…） | 永远有点用 —— 代价是**利息更高**（每次 +0.25 倍） |
  | 骂它（"杂鱼"、"菜"…） | **反噬**，掉心情值（它记仇时掉得更狠） |
  | 威胁它（"不还了"…） | **反噬**，掉得最狠 |
  | 没说到点上（"今天天气不错"） | 几乎没用 |

- 三轮说完，她**掷一个金额**：`roll = 心情/100 ± 0.3`，金额在
  [1000 万, 借出上限] 之间按 roll 插值，取整到百万。
  **心情越高，掷出高额的概率越大**；roll 太低（她根本不想给）就直接拒绝。
- 可以点下面的"快速说"按钮把模板填进输入框，也能自己改。

**分工和整局游戏一致 —— 模型只说话，代码算账**：接了 DeepSeek 时，
她回你的那句话由模型现编（提示词里会告诉它"你现在心情多少，该松口还是该损他"），
但**心情值、金额、利息、欠条全都由本地纯函数算**，模型改不了账本
（单测里有一条就是"模型给了台词，但心情值照样按本地规则走"）。

**② 重新开始** —— 代价是**它把你忘干净**：人格、战绩、欠条全部清零。

**钱从它自己的筹码里出**（保持零和），而且必须给它留够底注 ——
所以它自己也快见底的时候，你只能重新开始。借了要还：**赢的钱一半先还债**，
还完为止；顶栏右侧一直挂着"欠它 X"。

## 下注额随局数上涨

**开局 2000 万身家，第一档最小注 20 万，每 2 局升一档，第 20 局封顶（顶档 1000 万）。**
最大注 = 最小注 × 5（`BjMachine.STAKE_MIN_STEPS` / `STAKE_HANDS_PER_LEVEL`）。

> **术语说明**：这里**不叫「盲注」**。盲注是德州扑克里"发牌前强制押上的注"，
> 本作没有任何强制下注 —— 注是你自己选的。所以按用户的说法叫
> **最小注 / 最大注**（早期版本我误用了"盲注"，已全项目改掉）。

| 局数 | 最小注 | 最大注 | | 局数 | 最小注 | 最大注 |
|---|---|---|---|---|---|---|
| 0-1 | 20万 | 100万 | | 10-11 | 100万 | 500万 |
| 2-3 | 30万 | 150万 | | 12-13 | 150万 | 750万 |
| 4-5 | 40万 | 200万 | | 14-15 | 200万 | 1000万 |
| 6-7 | 60万 | 300万 | | 16-17 | 300万 | 1500万 |
| 8-9 | 80万 | 400万 | | 18-19 | 500万 | 2500万 |
| | | | | **20+** | **1000万** | 5000万（被身家压到 2000万） |

设计意图：档位是手写的整数（约 ×1.5 一档，不是 1.5^n），读数干净；
**顶档 1000 万 = 半副身家，刻意不设成全部身家** —— 如果封顶就等于全部身家，
第 20 局之后每局都成了"必然全押"的突然死亡，太惩罚；留一半还能继续打，纪录也还有得涨。
到了顶档，最大注（5000 万）已超过开局身家，所以 **ALL IN 按钮会在第 18 局前后自然出现**。

> **三次调参记录**（都是用户要求）：
> ① 开局从 1 亿降到 **2000 万**、第一档最小注从 100 万降到 **20 万**
>    —— 原来 100 万对 1 亿身家，赢了跟没赢一样；
> ② 升档从"每 10 局"改成"每 5 局"；
> ③ 再改成"**每 2 局**"，**第 20 局封顶**（顶档从 2000 万降到 1000 万，理由见上）。
>
> 连带调整：借钱上限 1 亿 → 2000 万、最低借款 1000 万 → 100 万、
> 借款取整到 10 万（原来百万）、人格判定的"赢着钱"归一到 8000 万。
> 旧存档靠 `BjProfile` 的 **v2 → v3 经济重定标迁移**自动结算：
> 筹码/局号/最高纪录/净收益归零，**胜负场次与人格倾向保留**。

### 在哪儿能看见它在涨

顶栏排成两行（**别把下注信息塞进局号那一行 —— 会压住"你 X token"**）：

```
第 30 局        你 2000万 token     鲸鱼娘 2000万 token    ┌它的战绩────────┐ ┌规则┐┌战绩┐┌设置┐
下注 20万 ~ 100万　·　2 局后升到 30万                       │0胜·0负·0平 净±0 最高2000万│
```

第二行会**按情况变脸**（`_refresh` 里那段）：

| 情况 | 显示 | 颜色 |
|---|---|---|
| 正常 | `下注 20万 ~ 100万　·　2 局后升到 30万` | 灰 |
| 已到顶档 | `下注 1000万 ~ 2000万　·　已到顶档` | 灰 |
| **下一档付不起** | `… 下一档最小注 60万，你只剩 25万` | **红** |
| **连底注都付不起** | `下注至少 80万，你只剩 30万 —— 付不起底注了` | **红** |

后两种就是"你正被涨注赶下牌桌"的时刻 —— 提前告诉你，而不是下一局突然不让你下注。

- **升级时弹横幅**：`下注额上调！　第 2 档　最小注 20万 → 30万　·　最大注 150万 token`
- **下注面额跟着换**，也可以直接按 **1 / 2 / 3** 选（不用鼠标）
- **规则页第 ④ 条**专门写了这条规则，而且**数字是从常量现算的**（见下）

> 说明书曾经骗过人：改成"每 2 局升档"之后，规则页还写着"每 10 局"。
> 现在 `rules_text()` 用 `%` 占位符从 `BjMachine` 的常量现算档位/封顶/倍数 ——
> 调经济再也不会让说明书漂移。

> 顶栏布局踩过两次坑：下注挤进局号那行压住了玩家筹码；「规则」按钮被右上角
> 战绩框盖住。现在 `test_ui.gd` 里有一条**顶栏元素两两不重叠**的断言，
> 按最长文本（第 999 局 + 10 亿级数字）算矩形 —— 它已经抓出过两次真实重叠，
> 包括 8px 的行高误差（`Label` 的实际高度不能按字号估）。

- 下注面额固定是 **[最小注, ×2, ×5]** 三个（超出可开注额的不给）。
- **`ALL IN` 按钮只在"最大注超过你拿得出的钱"时出现**（用户定的规则）。
  例：第 50 局最小注 1000万、最大注 5000万；你有 3000万 → 出现 ALL IN，
  面额只剩 [1000万, 2000万]；你有 1亿 → 不出现，面额是 [1000万, 2000万, 5000万]。
- 涨注涨到你付不起底注 → 直接进**破产流程**（跟输光一样）。
- ALL IN 依然不受最大注限制，只看**更穷的那一方**：
  `all_in_stake() = min(你的筹码, 它的筹码)`。

> **桌上筹码规则**：黑杰克要赔 1.5 倍，满注时对方可能被"赔穿"。
> 所以摊牌时赔付会被压到输家剩下的筹码（`settle()` 里的 clamp）——
> 这是 400 局连打的单测抓出来的（筹码变成负数）。

## 她的点数：看得见的部分直接报出来

**玩家不该被迫做心算。** 她那张暗牌是唯一隐藏信息，其余全部自动显示：

| 时机 | 显示 | 说明 |
|---|---|---|
| 你的回合 | `9 点 + ?` | 只算**看得见的**那张，`+ ?` 提醒还有暗牌 |
| 她翻开暗牌后 | `13 点` | 她的**真实点数**，之后每补一张都会跟着涨 |

为此把规则改成**标准 21 点**：她在自己回合**先翻暗牌、再补牌**
（原来她会在暗牌还没翻的时候就补牌，于是"看得见的点数"可能超过 21，
玩家算不明白）。现在她在自己回合补的每一张都是明的。

### 点数也是滚出来的（双方都有）

**数字全程挂在屏幕上，一路往上滚**（`_roll_points`，0.45 秒缓出）。实测一局：

```
你：0 点 → 4 点 → 9 点 → 12 点 → 13 点 → 14 点
她：0 点 + ? → 3 点 + ? → 5 点 + ? → 7 点 + ? → 8 点 + ?
```

- **双方都滚**（`player_total` / `opp_total` 各一条 tween，各自记"现在滚到几点"）。
- **任何时候都不清空文字**。用户的原话是"他不是先消失后再出现，是**滚动向上的**"——
  早期实现为了"别让点数比牌先出来"，会在牌还在飞的时候把标签**清空**，
  于是看起来就是数字先没了、再冒出来 ✗。现在改成：牌在飞时**保留旧值不动**，
  牌一落位就从旧值往上滚。
- **一局结束滚回 0**（0.2 秒），下一局再从 0 往上滚 —— 是"滚回去"而不是"清空"，
  而且不会出现从上一局的 20 点倒着滚到 5 点那种"像扣分"的观感。
- 爆牌落成 `25 点 · 爆牌` 并染红；黑杰克落成 `21 点 · 黑杰克`。
- 她暗牌没翻时后缀是 ` + ?`，**滚动过程中也带着后缀**（否则那个 `+ ?` 会一闪一闪）。
- 后缀只写 ` + ?`，不写 ` 点 + ?` —— 数字那部分已经带"点"了，
  否则会显示成 `6 点 点 + ?`。

> `tests/test_ui.gd` 里有一条回归断言 **`test_point_labels_never_go_blank_mid_hand`**：
> 牌还在飞的时候，两个点数标签都不许是空串。这类"闪一下"的问题肉眼很难复现，
> 交给断言最省事。

## 怎么玩（规则说明页）

顶栏 **「规则」** 按钮，**第一次进游戏自动弹一次**（看过就记进 settings 的
`seen_rules`）。正文是一份 BBcode 说明书，覆盖：

对注制 → 比点数（含黑杰克 1.5 倍）→ 你能做的事 → **下注每 2 局涨一档、第 20 局封顶** →
全押按钮何时出现 → 输光了怎么办（求情/重开/说错话会掉好感/越借越难）→
她输光了怎样 → 右上角那串数字是什么 → 快捷键 → 最后一句是彩蛋提示。

> 为什么必须写：这套规则**不是普通 21 点**（没有庄家、对注制、涨注、靠嘴借钱、
> 戳她三次会被干掉）。不写清楚，玩家只会觉得"这游戏在坑我"。

> 布局坑：`RichTextLabel` 的 `fit_content` 和 `ScrollContainer` 会互相等 ——
> 不给死宽度的话，宽度会塌成 1px、每个字一行、高度一万七千多，正文整页空白。

## 黑杰克专属反馈

拿到黑杰克（`player_hand` 两张 21 点）时，**等牌落位**后弹中央横幅：

> **BLACKJACK！**
> 1.5 倍筹码奖励　·　本局 500万 token

配上 `blackjack` 音效 + 全屏泛光 + 冲击波框 + 筹码飞向自己。同一局只播一次。

## 历史最高筹码

- 存档里的 `best_chips`，**跨局、跨"重新开始"都保留**（那是长期目标）；
  右上角战绩面板常驻显示 `最高 X`。
- 打破纪录 → 横滚的筹码数字跑完之后弹 **「新纪录！」** + 上次的数值。
- **借钱进来的钱不算纪录**：只有摊牌结算后的筹码才会刷新它，
  否则"借钱冲纪录"太廉价。

## 筹码数字滚动

顶栏的筹码不再直接跳字，而是**滚**过去（`_roll_to`，**0.75 秒**三次缓出），
而且**三个层次一起上**，确保"输赢"一眼看得出来：

| 层次 | 表现 |
|---|---|
| **数字滚动** | `你 2000万 → 1964万 → 1938万 → 1920万 → 1909万 → 1900万` |
| **方向染色** | 滚动期间标签染成**绿（涨）/ 红（跌）**，滚完淡回白色 |
| **飘字** | 标签右侧浮出 **`+450万` / `−100万`**，上飘 34px 后淡出 |

> **为什么加了后两层**：只做滚动时用户反馈"还是没做出来"。查下来滚动本身是好的
> （实测 2000万 → 1900万 一路滚 ✓），但**经济调小之后一局只动 1~5%**，
> 0.55 秒内数字尾数变几位，肉眼几乎看不出来。所以：时长加到 0.75 秒、
> 加方向色、再加一个绝对数值的飘字 —— 现在"这一下赢/输了多少"是明写的。

> 实现上有个坑：`_refresh` 一局里会被调用很多次（每次 `state_changed`），
> 而 `_roll_to` 每次都拿同一个目标重入 —— 不区分的话动画会重播、飘字会刷屏。
> 所以额外记了 `_roll_targets`：**只有目标值真的变了**才滚 + 飘字。

## 求情：越借越难，说错话会扣好感

### 借钱的难度会**累积**

- 每借成功一次，`loans_taken` +1；下次求情的**起点心情值直接扣 16 分**
  （`LOAN_HISTORY_PENALTY`）。借过 0/1/2/3 次的起点大约 46 → 30 → 14 → 5，
  **越借越难借** —— 逼你迟早靠牌技而不是靠嘴。
- 求情面板会明说"你借过 N 次，它记得"。

### 说错话是**会扣**好感度的

以前是"只要不骂它就至少 +1"，等于说什么都不亏（用户报的问题）。现在：

| 你的话 | 判定 | 心情值 |
|---|---|---|
| 她吃这套（看它**现在的脾气**） | 装可怜 / 吹捧 / 激将 / 谈条件 | `+22 × (affinity − 0.85)` → 最多 +16 |
| 她不吃这套 | 同上，但 affinity 低 | **倒扣**（−5 ~ −15） |
| 没说到点上 | `none` | **−2** |
| 骂它 / 威胁它 | `insult` / `threat` | −18 ~ −32 |

**心情值被扣到底（≤5）→ 她不想听了**：对话立刻终止，判**彻底失败**，
一分钱都不借，只能重新开始。

> 关键词是**子串匹配**，所以词必须经得起"别的意思顺带命中"的检验 ——
> 曾经侮辱词里有 `"就这"`，于是 `"就这样吧"` 被判成骂它、一次扣 20 分。
> 现在有回归测试钉着（`test_intent_keywords_do_not_false_positive`）。

## CG（三张：输光 / 认输 / 你赢）

`assets/cg/` 下三个文件，**放进去就生效，没有就跳过**（不挡流程）：

| 文件 | 触发 | 她的台词（字幕 + 配音，已烤好） |
|---|---|---|
| `lose_all.png` | **你输光** → 播完才弹"求情借钱 / 重新开始" | 杂鱼，要不我借你点，代价吗…… |
| `give_up.png` | **你认输**（选"重新开始"，或求情求到一半放弃） | 杂鱼就是杂鱼，赢不过我 |
| `you_win.png` | **你把它打光**（尤其被 ALL IN 清空） | 我的token……哭 |

规格 1280×760、建议像素风。画面上会压三行字：小标题在顶部 `y=42`，
她的台词在下沿 `y=628`（26px 金色），`y=672/702` 是提示与"继续"按钮 ——
所以这两条带子别放关键内容（三行字都带**深色描边**，压在任何底图上都读得清）。

**缓慢浮现**（约 3 秒，`bj_table_view.gd` 顶部那几个 `CG_FADE_*` 常量可以调）：

1. 黑场淡入（0.30s）
2. CG 画面淡入（1.10s）同时从 **1.06 缓慢推到 1.0**，像"压过来"
3. 小标题淡入（0.45s）
4. 她的台词淡入（0.55s）—— **台词浮现的那一刻才开口念**，声音和字幕对齐
5. 提示与"继续"按钮淡入（0.35s）

浮现过程中**点一下是"跳过动画"**（直接落到终态），再点一下才翻页 —— 不会误触跳过整张图。
播放时会响一声 sting（你输 `bust` / 你赢 `blackjack`）并停掉旧语音。

三句台词都已经烤进 `assets/voice/xiaoyi/`，CG 一出来就会念，**没有合成延迟**。

## 彩蛋：戳鲸鱼娘

**鼠标点它会生气，一共三次机会，一次比一次凶**（`bj_table_view.gd` 的 `POKE_LINES`）：

| 次数 | 它的台词（配音已烤好） | 表现 |
|---|---|---|
| 1 | 别点我。 | `angry` 表情 + 抖 4px + 红光 |
| 2 | 我说了，别点我。 | 抖 11px + 更强的红光 + 屏幕晃 |
| 3 | ……你手是不是不想要了。 | **缓慢黑化** → **重力一击** → 战败 CG |

**第三次的完整节奏**（`_blacken_and_strike()`，约 2 秒）：

1. **充能**（1.25s）：切成 `black` 黑化立绘 + 立绘压一层冷紫 + 世界**整屏压暗** +
   低频轰鸣 `charge` + 全身发抖；
2. **一击**：`impact` 重击音 + **整屏白闪** + 满屏震动（5 步方波）+ 冲击波框；
3. **收黑**：世界留一层 55% 暗色，缓慢浮现战败 CG `poked.png`，
   字幕「你因为手贱，被鲸鱼娘干掉了」，同时念**「叫你手贱」**。

**素材**：生气用 `assets/whale/angry.png`、黑化用 `assets/whale/black.png`
（都是 4 帧 × 48×57），CG 用 `assets/cg/poked.png`。
**缺任何一个都能玩** —— 立绘回落到 idle，但抖动/压暗/白闪/音效/字幕照旧。

> 外援立绘常常不是标准规格（尺寸是 4 倍、带纯色底）。
> `tools/prepare_whale_extra.py` 负责规整：**按四角取底色抠图 + 横向等分 + 最近邻缩到 48×57**，
> 用法 `python tools/prepare_whale_extra.py <源图> assets/whale/black.png 4`。

彩蛋**不扣筹码，但你会被"干掉"**：CG 之后弹一页
「你被干掉了 —— 手贱是要付出代价的」，**只有「完全重开一把」一个选项**
（筹码 / 战绩 / 它对你的记忆全部归零），期间牌桌不接受任何操作。
这是用户定的规则：人都死了，没有"继续"。

## 它输光了会怎样

> 外援立绘常常不是标准规格（尺寸是 4 倍、带纯色底）。
> `tools/prepare_whale_extra.py` 负责规整：**按四角取底色抠图 + 横向等分 + 最近邻缩到 48×57**，
> 用法 `python tools/prepare_whale_extra.py <源图> assets/whale/black.png 4`。

## 它输光了会怎样

你把它打光（它付不起底注）时：

1. **它的筹码就停在 0** —— 顶栏显示 0，**不会自动变回 1 亿**；
2. 摊牌先演完（1.9 秒），然后**缓慢浮现庆祝 CG**（`you_win.png`）；
3. CG 之后弹一个选择页「**你把它打光了！**」：
   - **再来一局（它再掏 1 亿）** → 它补钱回来，桌子清空，接着打；
   - **先看看战绩** → 打开战绩面板。

把补钱做成**玩家的选择**而不是自动到账，是因为自动到账会让玩家觉得
"我刚赢的又被抹了"（这是用户报的问题）。`next_hand()` 里还有一层兜底：
万一 CG 被跳过，翻页时也会自动补，不让桌子卡在"它没钱"的状态。

## 牌面用的是你给的素材

**中央装饰花色 = 你提供的 `picture/whale_pips_*_13.png`**（四张 928×64、洋红底、
一行 13 格 = A,2..10,J,Q,K，每格是装饰强度不同的鲸鱼花色）。
`scripts/art/bj_pips.gd` 用 GDScript 重做了原版 `tools/prepare-cards.py` 的整条流水线：

1. **抠洋红用距离阈值**（RGB 欧氏距离 ≤ 90）而不是精确相等 —— 否则会留一圈粉边；
2. **等宽切 13 格再取格内包围盒** —— 实测格子间距不均（69~78px），按空白列切红桃会切出 14 段；
3. **内容在格内居中**（原版是底对齐）：底对齐是为了一整行图集看起来齐脚，
   但每张牌只显示一格 —— 底对齐会让"矮一点"的花色在牌面上越坐越低，13 张牌高度还各不相同；
4. 拼成 4 行 × 13 列的图集（936×224，行序 S,H,D,C），格 72×56；
5. 贴到牌面时缩到 **42×32 并贴着牌面中心放**（12..43，中心 27.5 ≈ 牌面中心 28）；
   原版放在 (2,18)，配合底对齐会让图案整体偏低 4~6 像素；
6. **缩小用覆盖率降采样，不能用最近邻**。72→42 是 0.583 倍，最近邻只是每隔
   ~1.7 像素取一个点，于是**1 像素宽的装饰线**（描边框、绶带、卷角）会被采样成
   断续虚线、甚至整条消失 —— 牌面上就只剩几根悬空的横线，
   原本"花色套在方框里"的 2、圆环的 10、带绶带的 8 全看起来像画错了。
   改用"目标像素覆盖的源块里只要有实心像素就实心"，细线就完整保留了下来；
7. **缩完再清一次碎点**：花色边缘与洋红之间有抗锯齿过渡像素（深紫），
   抠图阈值放不掉它们，缩放后会在牌面上留下孤立的紫点；
   这里对缩完的小图做连通块过滤，小于 5 像素的连通块直接抹掉。

角标（点数 + 小花色）**仍然是程序化的**：这是原版定下的分工 ——
AI 画的角标一定是歪的，而中央装饰图正需要表现力。

**整副牌只有一个墨色**：原版按花色分红/黑（红桃方块红、黑桃梅花墨），
但用户给的鲸鱼牌面四门都是统一深藏青，角标再分红黑就变成"一副牌两种风格"。
现在角标与中央花色统一用 `#061b6e`（直接从素材主体取色），四门只靠**形状**区分。

统一墨色带来一个必须解决的问题：角标压在中央花色上会**糊成一片**。
所以角标带一圈 1 像素的牌面底色描边（实物扑克也是给角标留白的），
代码见 `BjPixel.blit_grid_outlined()`；J/Q/K 的王冠标记同样先铺底再压墨。

绘制顺序上让**角标压在花色之上**，因为它横跨整张牌、会和右下角标重叠。

素材缺失时会自动回落到程序化的 16×16 花色字模，牌面不会开天窗；
`test_art` 里有 10 项专门盯这条链路（抠图无洋红残留 / 52 格全非空 /
**图案在牌面与格内都居中** / **图案与牌面中央都没有孤立碎点** /
**1 像素细描边在缩放后四条边都还在** / **四门同一个墨色、牌面上没有红墨** /
**角标有描边（压在花色上也读得出来）** / **逐像素等于素材** / 纹理复用）。

## 声音：**一个声线**，配音是"烤"出来的

原来的语音用的是 Windows 自带的 SAPI（`DisplayServer.tts_speak`，pitch 还调到了 1.4），
又尖又顿，是这一版里最拉胯的地方。现在换成微软的神经语音（`edge-tts`，免费、无需 Key），
**而且只有一个声线** —— 分三级查找，逐级降级：

1. **烤好的素材** `assets/voice/<音色>/<hash>.mp3`
   固定台词（184 条）用 `tools/bake_voice.py` 一次烤好，永远命中；
2. **运行时现烤缓存** `user://voice_cache/<hash>.mp3`
   接了真模型之后它现编的句子是无限的，烤不完 —— 所以第一次说某句话时，
   游戏后台拉起 `tools/tts_one.py`（**同一个音色**）现烤一份存下来，
   以后同一句直接命中。这就是"为什么会听到两种声线"的根治办法。
3. 实在烤不出来（没装 edge-tts / 没网）→ **静音**。
   **不再回落到系统 TTS**：宁可这句不响，也不要突然换一个人说话。
   （想要旧行为可以在 `settings.json` 里把 `voice_fallback` 打开。）

细节：

- 台词走**临时文件**递给 python，不走命令行 —— 台词里有引号、换行、♡，命令行转义迟早翻车；
- 现烤是**非阻塞**的：起进程后每帧轮询输出文件，烤好了**自动补播**（上限 6 秒）；
  台词已经在气泡里打字出来了，声音稍晚一点反而像"跟着字幕念"；
- 合成好的 mp3 用 `AudioStreamMP3` 直接吃字节，**不走资源导入**，所以 `user://` 里
  刚生成的文件能立刻播；
- 设置里有 **「在线配音：开（现编台词现烤）」**，可以关掉只播烤好的那批；
  本机没 python 时这一行会显示"不可用"。

### 换音色 / 重烤

```
python tools/bake_voice.py --list      # 看有哪些中文音色
python tools/bake_voice.py xiaoxiao    # 换成"温柔自然"的那档重烤
```

音色表在 `tools/bake_voice.py` 的 `VOICES` 里（`xiaoyi` 活泼 / `xiaoxiao` 温柔 / `xiaobei` 东北腔），
运行时那个脚本用的是同一张表。哈希算法两边必须一致：
`sha256(utf-8 原文) 的前 16 位十六进制`，Godot 侧是 `text.sha256_text().substr(0, 16)`。

## 桌布背景

`assets/background/table.png` —— 用豆包按"深海赌桌"提示词生成的那张（1280×760 原生尺寸）。
`bj_table_view.gd` 会先看这个文件：**有图就用图**，**没有就回落到程序化的绿呢毯**，
设置里还有一行 **「桌布：图片 / 程序化绿呢毯」** 可以随时对比切换。

画法要点（`_draw_background`）：

- **按"铺满 + 居中裁切"画**（`cover` 而不是拉伸）—— 素材比例和目标不一致时不会变形；
- 图按**整个窗口 1280×760** 构图，但顶栏（68px）和手牌区（200px）是不透明的，
  **真正露出来的只有中间 1280×414 那条横带**，所以中间必须空、暗、干净；
- 画完压一层 **22% 暗色** + 上下各 40px 的暗角，保证奶油色牌面和金色文字始终压得住；
- 呢毯上下沿的金色/木色收边保留，桌子才有边界感。

生成这张图用的提示词、构图说明（哪条横带会露出来、中间要空要暗）都写在上面那段，
可以直接拿去重出一条不同风格的。

## 移植过程中自己踩的坑（都有单测兜住了）

- `".# ".contains("#")` 恒为真 → 所有实心像素被当透明跳过，**52 张牌面全空白**。被 `test_art` 的逐像素断言抓到。
- 对手回合里**只构建了一次视野** → 它整局照着开局那两张牌出牌，20 点还在要牌直到爆。现在每轮重建视野，并有回归测试。
- `view_of()` 直接返回引擎内部数组的**引用** → 视野不是快照，调用方能隔空改引擎状态。改成深拷贝。
- 编辑器**无法热重载"附加在当前场景根节点上的脚本"**：改完这类脚本必须重启编辑器，否则测试跑的还是旧代码（现象是报错行号对不上）。
- **气泡高度不能用 `Label.get_minimum_size()` 估**：自动换行时它给的是一段不可靠的估算，
  台词一超过两行文字就溢出到框外面（"对话框对不上"）。改成直接问字体要行高
  （`Font.get_multiline_string_size`），并有回归测试：长句必须把气泡撑高、留白要装得下文字。
- **判意图时负面词必须优先**：一句"你不还我就等着"里同时含"还"（谈条件）和"不还"（威胁），
  按命中数取最多会让嘴硬反而涨心情值。现在先扫威胁/骂人，命中就立即定性。
- **时序要以玩家看到的为准**（三条都是用户报的）：
  1. **它的点数要等暗牌翻完再出现**。原来 `_refresh` 一收到状态就写点数，
     可翻牌动画还有 0.42 秒 —— 牌没翻过来就先报点数，看着像它偷看牌。
     现在翻牌那一帧只显示"—"，翻完（`TOTAL_REVEAL_DELAY`）才补上点数。
  2. **CG 要等这一局演完再浮现**。原来破产信号跟着摊牌信号背靠背发出来，
     一把梭输光会**连自己几张牌都没看见就进 CG**。现在 `_on_bankrupt` 先
     `await _hold_for_showdown()`（1.9 秒：翻牌 → 点数 → 结果条），期间把
     "再来一局"**置灰**（而不是默默无视点击）。
  3. **`MOUSE_FILTER_STOP` 的图层会吃掉鼠标事件**。CG 那层是全屏遮罩，
     所以"点一下继续"挂在 `_unhandled_input` 上根本收不到点击 ——
     玩家只能精准点中"继续"按钮，其余地方点了像死机（用户报的"按钮按不了"）。
     改成挂 `cg_layer.gui_input`，整层任意点击都算继续。
  4. **补钱不能抢在 CG 前面**。原来她输光的瞬间就 `opponent_chips = 1 亿`，
     于是玩家刚赢完、顶栏已经显示她又有 1 亿了，"赢了个寂寞"。
     现在只发信号，补钱挪到 CG 之后（`opponent_buy_in()`）。
  5. **遮罩必须显式设尺寸**。`set_anchors_preset(FULL_RECT)` 在 `_build()` 里调用时
     父节点尺寸还是 0，遮罩层实际是 **0×0** —— 鼠标直接穿透到背后的下注 / 发牌 /
     再来一局按钮上，玩家能在"借钱 or 重开"的提示框上把下一局发出去。
     现在遮罩统一"锚点归零 + 显式 `size = 窗口尺寸`"（留 FULL_RECT 锚点又设 size，
     引擎会覆盖并报警告）。
  6. **有弹窗时牌桌按钮一律置灰、键盘快捷键一概不响应**。统一挂在各遮罩的
     `visibility_changed` 上重算（`_sync_modal_buttons`），不用在每个显隐分支里手写。
  7. **点数要等牌动完才出现**。之前只处理了"摊牌翻暗牌"，发牌时点数还是比牌先冒出来。
     现在 `BjHandView` 记下每次发牌 / 翻牌动画的结束时刻（`anim_remaining()`），
     视图按它决定点数何时出现 —— 发牌、要牌、摊牌三种情况统一了。
  8. **面板里的东西要挂在面板上，别挂在全屏遮罩上**。设置底部那三个按钮
     一开始挂在遮罩上，坐标基准变成屏幕，按钮直接跑到面板左边去了。
  9. **「再来一局」按钮已删除**：结算之后下注栏本来就回来了，直接按"发牌"就是下一局 ——
     它既没用（点了看不出变化），又是卡死的疑点。
  10. **别用布尔标志做"暂时锁住"**。摊牌期间的锁原来是 `_settle_hold = true/false`，
     一旦协程被打断就永久为真，**整张桌子锁死**。改成记时间戳（`_showing_down()`），
     最多锁 `SHOWDOWN_HOLD` 秒，卡不死。
  11. **补牌不该套用开局的错峰延迟**。错峰按"牌在手上的索引"算，于是你要的第 3 张牌
     要先干等 0.64×2 秒才飞出来 —— 表现就是"要牌之后半天没反应、音效也慢半拍"。
     现在错峰只用于开局那 4 张，后续补牌立刻飞（`anim_remaining` 从 1.28s 变 0.21s）。
  12. **音效要等牌落位再响**。`_on_action_events` 原来收到事件就播 `bust`，
     可牌还在半空、点数还没出。现在先把牌摆上、拿到 `anim_remaining()`，
     再用 `_delayed_sfx` 让"牌落位 + 点数出现 + 音效"同一时刻发生。
  13. **遮罩要有"自愈"**。`_process` 里每帧检查两种死状态并自动解开：
     遮罩亮着却一页都没有 / CG 停在"浮现中"但补间早没了。宁可少弹一个面板，
     也不能让玩家卡在一层点不到东西的遮罩后面。
- **求情页的立绘缩放要在 `add_child` 之后设**：`_ready()` 会照 manifest 里的 scale 覆盖一次，
  设早了会被改成 4 倍，把气泡挤到按钮底下（截图才发现）。
- **烘焙配音的哈希两边必须一致**：Godot 是 `sha256_text()`、Python 是
  `hashlib.sha256(text.encode("utf-8"))`，都取前 16 位十六进制。有一条活体验证：
  `has_clip("Blackjack！杂鱼♡")` 必须为 true，否则就是两边对不上。
- **"两种声线"是设计漏洞不是随机 bug**：烤好的固定台词走神经语音，
  而接了真模型之后**现编的无限多句子**没有素材，就掉回 Windows 自带机器人声 ——
  于是一句话小鱼、一句话机器人。修法不是"再烤一批"（烤不完），
  而是**运行时现烤 + 永久缓存**，并且把系统 TTS 兜底默认关掉（宁可静音也不换声线）。
- **PowerShell 写 JSON 会带 BOM**：`Set-Content -Encoding UTF8` 在 Windows PowerShell 5.1 下
  写出的文件开头有 BOM，Python 的 `json.load` 直接报错。Python 侧统一用 `utf-8-sig` 读。
- **给 python 传中文参数要走文件不走命令行**：台词里有引号/换行/♡，
  `OS.create_process` 的参数转义在 Windows 上很容易翻车，改成写临时文件再传路径。

## 接真的 DeepSeek

设置面板 → 填 **DeepSeek API Key** → 打开「对手大脑：DeepSeek API」。
不填 Key 时这个开关不会生效，游戏始终走本地大脑。

接上之后：

- 提示词沿用原版结构：**模型只做决策不做算术**（只回 `{action, say}`，非法动作由引擎拒绝）。
- **隐藏信息是协议层面的硬边界**：发给模型的字段是白名单 —— 牌靴里有什么牌它根本收不到
  （`test_llm` 里有断言：视野里只有"还剩几张"）。
- 单挑还给了它一个真实优势：**你的两张牌是明牌**，提示词会直接告诉它"你现在领先 3 点 / 落后 4 点"。
- 反脆弱：非法/超时/乱码 → **重试一次**（并把错误原样告诉它）→ 仍失败就降级到本地策略。

## 已知边界

- **分牌 / 保险 / 投降**没做（与原版第一版范围一致）。
- 单挑里它后手、且看得见你的牌，先天占一点信息优势 —— 你的反制手段是"该停就停 + 加注要谨慎"。
- 语音用系统 TTS（`DisplayServer.tts_*`），中文音色取决于系统；没装 TTS 时开关会置灰。
- 窗口按 1280×760 设计，改窗口大小会重排，但没做多平台适配。
- 真模型路径**没有联网实测过**（没有 API Key），但提示词构造与解析容错有 14 项离线单测。
